# ArUco Web

**Веб-адаптация / производный форк [GeBondar/aruco_map_generator](https://github.com/GeBondar/aruco_map_generator).** Оригинальный генератор карт и алгоритм размещения созданы GeBondar. Эта версия переносит генерацию в браузер и добавляет интерфейс. Подробнее: [upstream/ORIGIN.md](upstream/ORIGIN.md).

## Возможности

- 22 словаря OpenCV: ArUco 4×4, 5×5, 6×6, 7×7 (50/100/250/1000), ArUco Original, MIP и AprilTag. Всего 9846 рисунков.
- Сетка по числу колонок/рядов, размеру маркера и диапазону ID. Расстояния между крайними центрами или шаг между соседними.
- Отдельное поле для печати; ручная таблица и полный TXT-редактор; загрузка TXT и пример из исходного репозитория.
- Предпросмотр с сеткой, ID и масштабированием. Предупреждения о перекрытии и выходе за холст.
- Экспорт SVG, PNG и TXT. Данные остаются на устройстве; никаких аккаунтов, API и внешних шрифтов.

## Запуск

Нужен Node.js 20+. Приложение и сборка не имеют npm-зависимостей.

```sh
npm run dev
```

Откройте `http://127.0.0.1:5173`. Для автономного файла:

```sh
npm run build
```

Откройте `dist/index.html` двойным щелчком. Это один HTML-файл со встроенными стилями, кодом, словарём и примером. Его можно перенести на другое устройство или разместить на любом статическом хостинге. `npm run preview` обслуживает сборку локально.

## TXT и единицы

```text
# dictionary: DICT_4X4_50
# id length x y z rot_z rot_y rot_x
1 0.185 0.8 0.152 0 0 0 0
2 0.185 -0.8 0.152 0 0 0 0
```

`length` — полная сторона маркера в метрах, включая чёрную рамку, но без белого поля. `x` и `y` — координаты центра в метрах. Ось X направлена вправо, Y вверх. Начало координат — центр холста. Используйте точку в десятичных числах; допускаются научная запись, пробелы/табуляции и строки комментариев, начинающиеся с `#`.

`z`, `rot_z`, `rot_y`, `rot_x` сохраняются при импорте, редактировании таблицы и экспорте TXT. **Они не применяются к 2D-карте**, как и в исходном проекте. Их можно редактировать в TXT.

Экспорт записывает словарь в комментарии `# dictionary: …`. При импорте словарь восстанавливается автоматически. Старый TXT без этого комментария использует текущий выбранный словарь.

По умолчанию: поле 2 × 2 м, 1000 px/м (2000 × 2000 px), словарь DICT_4X4_50. Холст: до 8192 px по стороне и 32 миллионов пикселей суммарно; до 1000 маркеров. Для распознавания оставляйте белый промежуток между маркерами и краями карты.

## Генерация сетки

Задайте ширину и длину печатного поля, затем число маркеров по ширине и длине, размер маркера и диапазон ID включительно. Используются первые N ID диапазона слева направо, сверху вниз.

Режим «Между крайними» задаёт расстояние между центрами крайних маркеров по обеим осям. Режим «Между соседними» задаёт шаг между соседними центрами. При переключении сохраняется геометрия: `span = step × (count − 1)`. Если по оси один маркер, он расположен по центру и расстояние равно нулю.

Полные габариты сетки равны расстоянию между крайними центрами плюс размер маркера. Они должны помещаться в печатное поле. Шаг должен быть больше размера маркера, чтобы оставался белый промежуток.

«Создать сетку» заменяет текущую карту и центрирует сетку на поле. Изменение параметров без этой кнопки карту не заменяет. При ошибке (нехватка ID, перекрытие, выход за поле) текущие маркеры сохраняются. После генерации можно менять любую строку и добавлять отдельные маркеры.

## Экспорт и печать

SVG содержит векторные прямоугольники и физический размер поля в миллиметрах. Например, поле 0.21 × 0.297 м даёт SVG 210 × 297 мм. PNG имеет размер поля в пикселях, полученный умножением метров на px/м. Сетка, оси и подписи ID не экспортируются. У вручную размещённых маркеров, выходящих за холст, обрезаются края. Мелкие маркеры в PNG могут не распознаваться.

Для SVG выберите в программе печати **100% / фактический размер** и отключите подгонку страницы. В PNG физический размер страницы не записывается: задайте его вручную в программе печати. Проверяйте размер напечатанного маркера линейкой.

## Проверки

```sh
npm test
npm run build
```

Браузерные проверки требуют Playwright (только для разработки):

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

Проверяются импорт, редактирование, ошибки, сохранение восьми колонок, реальные скачивания и мобильная ширина. `TEST_URL` позволяет проверить запущенный сервер; `TEST_FILE` — абсолютный путь к автономному HTML. `CHROMIUM_PATH` задаёт путь к уже установленному Chromium; `PLAYWRIGHT_MODULE` — к доступному модулю Playwright.

Независимая проверка всех 9846 матриц, SVG всех словарей и реальных скачанных PNG через OpenCV:

```sh
python -m pip install opencv-python numpy
node tests/create-opencv-fixtures.mjs
python tests/verify_opencv.py
```

`python scripts/generate_dictionary.py` пересоздаёт `src/dictionary.js` из OpenCV. Python не нужен конечному пользователю.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает сайт и публикует `dist/` при push в `main`, после успешных проверок. В репозитории один раз выберите **Settings → Pages → Source → GitHub Actions**. После успешного запуска сайт будет доступен по адресу `https://nikilokser.github.io/arucogen-web/`.

На pull request запускается отдельный workflow `checks.yml` с тестами, сборкой и браузерной проверкой; публикация выполняется только из `main`.

## Структура

`src/core.js` — TXT, проверка данных, размещение и SVG; `src/grid.js` — геометрия сетки; `src/app.js` — интерфейс и PNG; `src/dictionary.js` — компактные словари OpenCV; `scripts/` — автономная сборка и сервер; `tests/` — проверки; `upstream/` — исходник и авторство.
